  - **테스트 결과**: signIn은 실제 브라우저로 별도 테스트 계정(admin API로 생성) 로그인 → 온보딩 안 된 계정이라 정상적으로 온보딩 화면으로 리다이렉트되는 것까지 확인(정상 동작). signUp은 코드 로직 자체(에러 노출 포함) 정상 확인했지만, 테스트를 여러 번 반복하다 Supabase 기본 이메일 발송 서비스의 **rate limit**에 걸려 실제 확인 이메일 발송까지는 못 봄 — **코드 버그 아님, Supabase 무료 티어 SMTP 자체 발송 한도** (수아가 나중에 Supabase 대시보드에서 커스텀 SMTP(Resend/SendGrid 등) 연결하면 실사용자 트래픽에서도 안전).
  - Supabase 프로젝트 설정 확인 결과: `mailer_autoconfirm: false` → 즉, 실제 서비스에서도 회원가입(이메일 변경) 시 확인 이메일을 클릭해야 이메일이 최종 반영됨(보안 기본값). 이대로 둘지, "Confirm email change" 끄고 즉시 반영으로 바꿀지는 수아가 결정할 사항(Supabase 대시보드 Authentication → Settings).
  - `npx tsc -b` 클린, 커밋 `beecfdb`로 push 완료, Vercel 배포 성공 확인(정적 페이지 200, 인증 없는 API 401로 정상 반응).

### 21. 20번 이후 추가 수정 (토큰 90%+ 시점)

### 23. 윤경님 push가 배포 안 되던 문제 — 근본 원인 파악 + GitHub Actions 배포로 전환

**문제**: 윤경님이 `main`에 push해도 Vercel에 자동배포가 안 됨(수아님이 윤경님 카톡 캡처로 전달받음).

**진짜 원인 (Vercel 대시보드 스크린샷으로 확정)**: Vercel Hobby(무료) 플랜의 **네이티브 GitHub 연동**은 "커밋 작성자(git author)가 해당 Vercel 프로젝트 멤버가 아니면 자동배포를 거부"함. 윤경님을 프로젝트 멤버로 초대하려 했으나 팀원 초대는 **Pro 플랜 전용 기능**("This feature is available on the Pro plan" 문구 확인) → Hobby 플랜에선 근본적으로 해결 불가능한 제약.

**대안 검토**: 저장소를 public으로 돌리면 되지 않을까 잠깐 논의했으나(수아님 "퍼블릭으로 돌리고 개발해야하나?"), Vercel의 배포 권한 제약과는 무관한 얘기라 의미 없음("그런다고 달라지는거 없지").

**해결책 (1차, 이후 25번에서 "완전히 맞지는 않았음"으로 정정됨)**: `.github/workflows/deploy.yml` 신규 작성 — main에 push되면 **수아님의 개인 `VERCEL_TOKEN`으로 Vercel CLI를 통해 수동 배포**를 트리거. 당시엔 이 경로가 네이티브 Git 연동(webhook)이 아니라 API 기반 수동 배포라 "커밋 작성자 멤버십" 제한을 안 받을 거라고 판단했음 — **이 판단은 절반만 맞았음, 25번 참고.**

- **보안 확인**: 수아님이 "이 3개 등록해도 SUPABASE_ANON_KEY 등 다른 게 유출되는 거 아니냐"고 재확인 → GitHub Actions secrets는 그 자체로 암호화 저장되고 로그에도 마스킹되어 노출 안 됨, 윤경님껜 이 3개 값 자체를 전달할 필요도 없음(그냥 push만 하면 자동으로 돌아감)이라고 설명 완료.

### 25. 23번 정정 — "CLI+토큰이면 author 제한 안 받는다"는 판단이 틀렸음, 진짜 최종 해결

23번에서 "GitHub Actions + 개인 토큰으로 CLI 배포하면 Vercel의 git-author 제한을 안 받는다"고 판단했었는데, **윤경님이 그 이후 또 push한 커밋(`bd032aa`, `866c3ec`)에서 이 판단이 틀렸음이 실제로 확인됨.**

- 수아님이 Vercel 대시보드 스크린샷을 보여줌: 윤경님 커밋(`bd032aa`) 배포가 재시도까지 포함해서 **두 번 다 "Blocked"**로 뜸.
- A/B 테스트로 확정: 같은 워크플로우(CLI+토큰 방식)로, **수아님 이름으로 된 커밋은 항상 30~50초 만에 성공**(`ca4fac2`, `db9343c`, `69b88ba` 등), **윤경님 이름으로 된 커밋은 항상 Blocked**(`bd032aa`, 재시도 포함 2회 다) — 즉 CLI로 배포해도 Vercel은 여전히 **"배포되는 HEAD 커밋의 git author"를 검사해서 프로젝트 멤버가 아니면 Blocked** 처리하고 있었음. 네이티브 Git 연동만의 문제가 아니라 Vercel Hobby 플랜의 더 근본적인 제약이었던 것.
- (참고: 윤경님 쪽 Claude가 "저장소를 public으로 돌리면 이 제한 대상이 아니다"라는 대안을 제시했었는데, Vercel 문서 근거가 명확하지 않고 이 제한은 GitHub 저장소 공개 여부가 아니라 **Vercel 팀/프로젝트 멤버십** 기준으로 보여서 채택 안 함 — 소스코드(SOLAR 프롬프트, 관리자 로직 등) 공개라는 실질적 비용만 발생시킬 위험이 있다고 판단함.)

**진짜 최종 해결책**: `.github/workflows/deploy.yml`에 체크아웃 직후, 빌드/배포 전에 **빈 커밋(empty commit)을 하나 얹어서 그 배포 러너 안에서만 HEAD의 git author를 수아님 계정으로 정규화**하는 스텝 추가(`git config user.name/user.email` → `git commit --allow-empty`). 이 커밋은 origin에 push되지 않고 러너 안에서만 존재 — 실제 코드/히스토리는 전혀 안 바뀜, Vercel이 보는 "배포 대상 커밋의 author"만 항상 수아님으로 보이게 만드는 방식.
- 커밋 `2f648fc`로 적용.
- 검증: 이 수정 적용 후 윤경님이 또 push한 커밋(`866c3ec`, 상단 근무 상태 배지 드롭다운 변경) — **author가 여전히 yoon-kyoung인데도 배포 정상 성공**(`30209466279`). 사이트 접속해서 렌더링도 정상 확인.

**퇴근 리포트를 한국어 교육 콘텐츠로 재구성**: 기존엔 `buildDailyReportPrompt`에 언어 지시가 없어서 잘한 표현/교정/총평이 전부 영어로 나오고 있었음(수아님 QA로 발견). 실제 영어 문장(`text`/`before`/`after`)은 그대로 두고, 그 설명(`note`/`summary`/`register_feedback` 등)은 한국어 교사 코멘트처럼 쓰도록 프롬프트 재작성. "필수 암기"(`recommended_expressions`)도 그동안 `getTodaySnapshot`에서 프론트로 아예 안 내려주던 죽은 필드였음 — `{en, ko, note}` 구조로 바꿔서 실제로 채워지게 연결(DB 컬럼도 `text[]` → `jsonb`로 마이그레이션, 수아님이 SQL 실행). `ReportsPage.tsx`도 영어 문장+한국어 설명이 같이 보이는 카드 형태로 재구성.

**회원가입/로그인 버그 여러 건**:
- 이메일이 화면엔 정상으로 보이는데 `"Email address \"\" is invalid"`로 빈 문자열 전송되던 문제 — 정확한 원인은 못 밝혔지만(크롬 자동완성이 `onChange` 없이 DOM만 채우는 케이스로 추정), 클라이언트 검증(제출 전 자체 이메일 형식 체크) + 제출 시점 `ref`로 실제 DOM 값 재확인 + blur 시점 동기화, 세 겹으로 방어해서 재발 안 하게 함.

**"고함항아리"(업무 스트레스 풀기) 신기능**: 수아님이 원한 두 아이디어 — (1) 외근 반복/미응답 누적 등 스트레스 신호 감지 시 동료가 먼저 위로+영어 격언/캐주얼 표현을 건네는 메시지, (2) 유저가 먼저 동료에게 캐주얼하게 말 거는 채널("마법의 소라고동") — 을 하나로 합쳐서 구현.
