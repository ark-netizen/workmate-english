# 부캐영어(WorkMate English) — 2026-07-27 작업 요약 (파트너 브리핑용)

## 1. 만족도 조사(설문) 기능 신규 구축

**무엇을 만들었나**
- 관리자가 설문 제목/설명을 작성하고 **"내용 저장" → "반영"** 순서로 진행하면, 서비스를 이용 중인 유저에게 화면 하단 배너로 설문 참여 요청이 노출됩니다.
- 설문 형식은 **별점(1~5) + 한 줄 후기** 고정 형식입니다.
- 관리자 페이지에서 응답을 실시간으로 확인할 수 있고, 응답이 쌓인 뒤 **"노출하기"** 버튼을 누르면 실제 유저 후기가 **소개(랜딩) 페이지 하단에 별점과 함께 4초 간격 롤링 배너**로 자동 공개됩니다.

**응답 출처 구분 (오늘 추가로 다듬은 부분)**
- 화면 하단 배너로 남긴 응답과, CS 챗봇을 쓰다가 남긴 응답을 **분리해서 집계**합니다.
  - 이유: 챗봇은 이미 불편/불만이 있는 상태에서 쓰는 경우가 많아, 같이 섞으면 평균 만족도가 왜곡될 수 있음.
- 관리자 대시보드에서 **"평균 별점(배너)"과 "평균 별점(챗봇)"을 별도 카드로** 확인 가능.
- 응답 목록에도 각 응답이 배너/챗봇 중 어디서, 챗봇이면 어느 단계(예시질문/자유질문/문의남기기)에서, 몇 번째로 남긴 응답인지 배지로 표시.

**배너 노출 조건 (스팸성 노출 방지)**
- 실계정(로그인 완료) 유저에게만 노출, 익명 체험 유저에게는 안 뜸.
- **오늘이 첫 방문(첫 이용일)인 유저에게는 노출 안 함** — 최소 2번째 이용부터 노출.
- 이미 배너로 응답한 유저에게는 다시 안 뜸.
- "나중에" 선택 시 **2주간 재노출 안 함**.
- (반면 챗봇 종료 시 뜨는 설문은 위 조건과 무관하게 매번 물어봄 — 그때그때의 만족도가 궁금하기 때문)

## 2. CS 챗봇 재설계 (우측 하단 플로팅 버튼)

**처음 버전**: "질문하기" / "문의 남기기" 두 탭을 나란히 배치 — 유저 피드백: 차이가 헷갈림.

**최종 버전**: 단계별 진행 흐름으로 재구성했습니다.

```
[질문 시작하기]
    ↓
자주 묻는 질문(프리셋) 노출 → 탭하면 즉시 사전 작성된 답변 표시
    ↓ "이외에 질문이 있으신가요?"
자유 질문 입력 → LLM이 실시간으로 답변 생성
    ↓ "담당자에게 문의 남기기"
문의 내용 작성/제출 → 관리자 CS 탭에 접수되어 확인 가능
```

- 각 단계마다 **"종료하기"** 버튼이 있고, 누르면 챗봇을 닫고 (실제로 대화를 나눴다면) 바로 이어서 만족도 조사가 뜹니다.
- 자주 묻는 질문(프리셋)은 힌트 사용법 / 외근 버튼 / 반차·연차 / 고함항아리 / 퇴근 리포트 등 실제 서비스 사용법 위주로 구성.

- 처리 대기 건수 스탯 카드 + 응답별 "처리완료로" 버튼 제공.

## 4. 개발 편의 기능 — "오늘 초기화" 버튼

- 문제: 하루에 한 번만 퇴근할 수 있어서, 같은 날 안에 출근→업무→퇴근 전체 흐름을 반복 테스트하기 어려웠음.
- 해결: 홈 화면에 **"오늘 초기화 (개발용)"** 버튼 추가 — 누르면 오늘 하루 기록을 통째로 삭제하고 출근 전 상태로 되돌려서, 콘솔 조작 없이 바로 재테스트 가능.

## 6. 설문 관리자 페이지 — 응답 관리 고도화

**응답 목록을 표 형태로 재구성**
- 카드 나열 → 열(작성자/출처/별점/후기/작성일시) 기반 **표**로 변경.
- 각 열 헤더를 클릭하면 오름차순/내림차순 정렬 가능.
- **출처(배너/챗봇 단계별) 필터, 별점 필터** 드롭다운 추가.
- **엑셀(CSV) 다운로드** 버튼 추가 — 현재 정렬/필터 기준 그대로 다운로드.
- "설문 내용 작성·수정" 영역을 접기/펼치기(폴딩) 가능하게 변경, 기본값은 펼침.
- 별점/후기 고정 항목 외에 **"+" 버튼으로 자유 질문을 추가**해서 응답자에게 더 물어볼 수 있음.

**"실제 후기" 노출 — 개인정보 보호 안전장치 추가**
- 처음엔 체크박스 하나로 노출 여부만 정했는데, 두 가지 문제가 있었음: (1) 실제 이름/원문 후기가 그대로 랜딩 페이지에 노출될 위험 (2) 체크박스 열이 표 오른쪽 끝에 있어 스크롤해야만 보이는 문제.
- 개선한 흐름:
  1. 응답 목록에서 노출 체크박스를 **표 맨 앞 고정열**로 옮겨 항상 보이도록 함.
  2. 체크박스를 켜면(체크) 바로 반영되지 않고, **편집 확인 팝업**이 뜸 — 여기서 노출될 "작성자 표기"(예: 실명 대신 "김**" 형태로 기본 마스킹 제안)와 "후기 문구"(회사명·이름·연락처 등 개인정보를 지우거나 마스킹할 수 있음)를 직접 확인/수정.
  3. 팝업에서 **"확인하고 노출"**을 눌러야 최종적으로 소개 페이지에 반영됨 — 취소하면 아무 것도 저장되지 않음.
  4. 체크 해제(노출 끄기)는 바로 처리.
  5. 소개 페이지에는 관리자가 확정한 마스킹 버전만 노출되고, 실제 이름/원문 후기는 절대 그대로 나가지 않음.

## 7. 근무 시간 트래킹 점검 결과

- 실제 DB 기반 트래킹 맞음(가짜/목업 아님) — 출근 버튼을 누른 시각(`started_at`)과 퇴근 버튼을 누른 시각(`ended_at`)을 각각 DB에 저장하고, 근무 시간은 그 두 시각의 차이로 계산.
- **웹페이지를 꺼도 동작함** — 근무 시간은 브라우저에서 초 단위로 카운트하는 방식이 아니라, 요청이 들어올 때마다(리포트/관리자 페이지 조회 시) "저장된 출근 시각"과 "저장된 퇴근 시각(아직 퇴근 전이면 현재 시각)"을 서버에서 다시 계산하는 방식. 그래서 탭을 닫거나 껐다 켜도 시간은 정확하게 유지됨.
- 다만 **"퇴근" 자체는 여전히 유저가 직접 눌러야 확정**됨 — 자동으로 퇴근 처리해주는 로직(자정 자동 마감 등)은 아직 없음. 유저가 퇴근을 안 누르고 다음날 다시 접속하면, 그 사이 시간까지 "근무 중"으로 계산될 수 있음(엣지 케이스). 필요하면 자정 기준 자동 마감 로직을 추가로 고려할 수 있음 — 지금은 별도 요청 없어서 그대로 둠.
