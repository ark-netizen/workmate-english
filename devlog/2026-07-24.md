### 2. 프론트 프로토타입 (로컬 전용, 참고용)
Vite + React로 프로토타입 구현 → 디자인 가이드 톤(업무용 B2B 웹앱)에 맞춰 개편.
- 좌측 사이드바 + 상단 상태바(근무상태·시간·알림) + 우하단 인앱 배너
- 메신저 2-pane(동료·상사) / 이메일 2-pane(거래처) — 채널 구분 확실히
- 이니셜 아바타·라인 아이콘(이모지/캐릭터 제거), 확인 모달, 리포트=회고 톤
- Service Worker + 웹푸시: 다른 탭/백그라운드일 때 OS 알림 (완전 종료는 백엔드 필요)
- **이건 윤경 님께 방향 보여줄 참고용. 수아 결과물 아님. 깃에 안 올림.**

### 3. DB 스키마 = 필드명 계약 (수아 담당 최우선)
- `db/schema.sql` 작성 (로컬): 13개 테이블 + 상태 enum + 인덱스
  - app_users, user_profiles, workdays, scenarios, characters, conversations,
    messages, notification_schedules, push_tokens, daily_reports,
    workday_memories, leave_records, rewards
- 상태값 enum 확정: `day_state`, `conversation_status`, `notification_status`,
  `channel_type`, `character_role`, `english_level`, `message_sender`, `leave_kind`

### 4. Supabase 세팅 (완료)
- 기존 프로젝트 재사용 (ref: `zchagwujhqjfteehexmp`) — 안 쓰던 프로젝트라 밀고 재사용
- SQL Editor에서 실행:
  1. `drop schema public cascade` + 재생성 (기존 데이터 초기화)
  2. 우리 스키마 적용 → **테이블 13개 생성 확인 ✅**
  3. 전 테이블 **RLS enable** → 현재 서버(service_role)만 접근 가능 상태
- ("Unable to find table ID 17694" 메시지는 옛 테이블 잔상, 무시)

### 5. 워크플로우 / 키 관리 정리
- **키는 코드에 안 들어감.** 코드는 env 변수 이름만(`VITE_SUPABASE_URL` 등),
  실제 값은 Vercel 환경변수 + 로컬 `.env.local`에만.
- 흐름: 윤경 님이 프론트 짜서 push/PR → 수아가 머지 + 키 꽂고 배포.
  → **키를 넘길 일 거의 없음.** (필요 시 anon 키만, service_role은 절대 X)
- 이 협업 방식은 이미 **공동개발 가이드 §7**에 문서화돼 있음 (추가 문서 불필요).
