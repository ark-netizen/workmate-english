# 몰입형 글로벌 오피스 영어 서비스 — 프로젝트 개요

> **Global Office** — 영어를 "공부하는 시간"을 따로 만들지 않고, **영어로 일하는 하루**를 경험하게 하는 몰입형 비즈니스 영어 서비스

- 배포: https://english-suasua1.vercel.app
- 저장소: `ark-netizen/english` (Private)

---

## 1. 한 줄 정의

사용자의 실제 **직무와 영어 수준을 반영한 동료·상사·거래처의 영어 연락**이 근무시간 중 **푸시 알림**으로 도착하고, 사용자의 답변에 따라 **이후 업무 상황과 퇴근 리포트가 달라지는** 몰입형 영어 학습 서비스.

---

## 2. 배경 및 문제 정의

기존 비즈니스 영어 서비스는 다음 한계를 가진다.

- 사용자가 **직접 학습 앱에 들어가** 주제를 고르고 대화를 시작해야 한다 (지속이 어렵다).
- "회의 잡기", "자기소개" 같은 **범용 상황**에 집중해, 본인 직무와 동떨어져 흥미가 낮다.
- 한 번의 롤플레이가 끝나면 **앞선 업무 맥락이 사라진다.**
- 동료·상사·거래처에 따라 달라지는 **말투(격식)를 통합적으로 경험하기 어렵다.**
- 실제 직장은 메신저·이메일·전화를 오가지만, 학습은 **단일 채팅창**에 갇혀 있다.

**핵심 통찰:** 사람들은 "영어 공부 시간"을 꾸준히 확보하지 못한다. 그렇다면 **공부하러 들어오게 하지 말고, 업무 연락처럼 영어가 먼저 찾아오게** 하자.

---

## 3. 서비스 목적

- 별도의 학습 세션 없이, **출근–업무–퇴근**이라는 익숙한 리듬 안에서 영어를 사용하게 한다.
- 사용자의 **실제 직무 상황**에 맞는 영어를 연습시킨다.
- 상대(동료/상사/거래처)에 따라 달라지는 **적절한 격식과 표현**을 체득하게 한다.
- 채점·정답 표시가 아니라 **실제 상대의 반응**으로 몰입을 유지하고, 교정은 **퇴근 후 회고**로 제공한다.

---

## 4. 핵심 타깃

해외 파트너·글로벌 조직과 일하고 싶지만 **실무 영어 경험이 부족한 직장인·취업준비생.**

- 영어 시험 성적은 있으나 실제 업무 응답 경험이 부족
- 별도의 영어 공부 시간을 꾸준히 확보하기 어려움
- 직무와 무관한 범용 콘텐츠에 흥미를 못 느낌
- 이메일·메신저·전화별 적절한 표현 수준의 차이를 어려워함

## 5. 핵심 차별성

| # | 차별점 | 설명 |
|---|--------|------|
| 1 | **학습을 시작하지 않아도 영어가 먼저 도착** | 사용자가 주제를 고르는 구조가 아니라, 출근 후 동료·상사·거래처가 **웹 푸시로 먼저 연락**한다. 브라우저 탭을 닫아도 알림이 온다. |
| 2 | **직무 맞춤 LLM 생성 콘텐츠** | 미리 만든 문장을 직무명만 바꿔 제공하지 않는다. 온보딩 정보(업종·직무·주요 업무·소통 대상)를 바탕으로 **매일 새로운 업무 시나리오를 생성**한다. |
| 3 | **관계별 언어 레지스터를 한 흐름에서 경험** | 같은 업무 사건이라도 **동료(캐주얼) / 상사(업무) / 거래처(격식)** 로 표현이 달라진다. 세 관계를 하루 동안 오가며 격식·직접성·구조의 차이를 자연스럽게 익힌다. |
| 4 | **채점이 아닌 상대의 반응 + 퇴근 회고** | 답변이 모호하면 실제 상대처럼 **되묻는다**. 대화 중엔 정답/오답을 띄우지 않고 몰입을 유지하며, 문법·표현 정리는 **퇴근 리포트**에서 종합 제공한다. |
| 5 | **채널 구분과 하루 연속성** | 메신저와 이메일 UI를 명확히 구분(Slack·Gmail 톤)하고, **오늘 답한 내용이 내일 시나리오로 이어진다.** |

## 6. 주요 기능

### 온보딩
- 업종·직무·주요 업무·소통 대상, 영어 수준(초/중/고급), 근무시간
- (선택) 동료·상사·거래처의 이름·성격 커스터마이징 → 생성 시 고정 반영

### 하루 업무 흐름
- **출근** → 그날의 **Workday 시나리오 + 세 인물**을 LLM으로 생성하고 연락 시간을 예약
- 근무시간 중 **동료 메신저 → 상사 메신저 → 거래처 이메일**이 시간차로 도착 (웹 푸시)
- 각 연락에 **한국어 힌트·예시 답변·핵심 단어** 제공 → 사용자가 영어로 답변
- 답변에 따라 상대가 **수용/재확인/협의/오해** 등으로 반응 (채점 아님)
- **외근**(남은 연락 지연 후 재알림), **반차·연차·출근취소** 지원
- **퇴근** → 오늘의 **영어 업무일지(리포트)** 생성

### 퇴근 리포트 (회고 톤, 성적표 아님)
- 오늘의 업무 요약 / 잘 사용한 표현 / 다듬으면 좋을 표현
- 상대별 말투 피드백 / 반복 오류 / 추천 표현 / **내일 이어질 업무**

### 근태·성취
- 출석 캘린더, 연속 출근, 마일스톤 뱃지

### 알림
- 웹 푸시(브라우저 종료 시에도 수신), 인앱 배너, 알림센터

## 7. 사용자 경험 흐름

```
소개(체험해보기)
 → 온보딩(직무·영어수준·근무시간)
 → 출근
 → [근무시간] 동료·상사·거래처 연락이 푸시로 도착
 → 영어로 답변 → 상대의 후속 반응
 → 같은 업무 사건이 세 관계로 이어짐
 → 퇴근 → 영어 업무일지(리포트)
 → 다음날, 전날 업무의 연장선에서 다시 출근
```

로그인 없이 **체험**으로 바로 시작하고, 이후 좌측 상단에서 **회원가입/로그인(이메일·카카오)** 하면 체험 데이터를 유지한 채 실계정으로 이어 쓸 수 있다.

## 8. 기술 스택 및 시스템 아키텍처

### 스택
- **프론트엔드:** Vite + React + TypeScript + Tailwind CSS, React Router
- **PWA/알림:** Service Worker + Web Push (VAPID)
- **백엔드:** Vercel Serverless Functions (Node)
- **DB·인증:** Supabase (PostgreSQL + Auth: 이메일/카카오/익명)
- **LLM:** Upstage **SOLAR (solar-pro2)** — 어댑터 구조로 교체 가능
- **스케줄링:** Vercel Cron (예약 알림 디스패치)
- **배포:** Vercel

### 아키텍처 개요
```
[브라우저 · React]
   │  (Supabase JWT)
   ▼
[Vercel Serverless API]
   ├─ 인증(Supabase JWT 검증)
   ├─ 오케스트레이션(출근~퇴근)
   ├─ LLM 생성(SOLAR) ── 시나리오·역할 메시지·후속 반응·리포트·익일 요약
   ├─ Web Push 발송(VAPID)
   └─ Supabase(Postgres) ── 사용자·시나리오·대화·메시지·리포트·알림 예약
        ▲
[Vercel Cron] ── 예약 시각 도달 알림 발송(브라우저 종료 상태에서도 도착)
```

### 보안 설계
- 서비스 키(Supabase service_role, LLM API, VAPID)는 **서버 함수에서만** 사용, 브라우저 미노출
- 프론트는 공개용 anon 키만 사용, DB는 **RLS**로 보호
- LLM은 한국어 번역이 아닌 **업무 상황+역할 기반 영어 직접 생성**으로 번역투를 줄이고 관계별 말투를 통제

## 9. 현재 구현 현황

**동작하는 MVP 핵심 흐름 (배포 완료):**
- 소개 → 체험/온보딩 → 출근 → 시나리오·인물 생성·저장
- 동료/상사/거래처 연락 생성 + 웹 푸시 + 답변 → 후속 반응
- 퇴근 리포트 + 익일 연속성, 외근/반차/연차
- 이메일/비밀번호·카카오·익명 로그인, 출석·마일스톤, 답변 힌트

**진행 중·후속:**
- 카카오 로그인 대시보드 설정(Redirect·Manual linking) 마무리
- RLS 정책 정교화, 디자인 다듬기
