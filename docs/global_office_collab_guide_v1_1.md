# 몰입형 글로벌 오피스 영어 — 공동개발 가이드 v1.0

> 목적: 서비스 핵심, 작업 경계, 우선순위를 함께 확인하고 각자 맡은 작업을 병렬로 진행하기 위한 문서

---

## 1. 서비스 한 줄 정의

사용자의 직무와 직급을 반영한 동료·상사·거래처의 영어 연락이 근무시간 중 도착하고, 사용자의 답변에 따라 후속 반응과 퇴근 리포트가 달라지는 몰입형 글로벌 오피스 영어 서비스입니다.

### 핵심 경험

```text
출근
→ 근무시간 중 영어 연락 도착
→ 메신저·이메일로 답변
→ 답변에 따른 상대방의 반응
→ 퇴근
→ 실제 답변 기반 영어 업무일지
```

---

## 2. 공통으로 유지할 서비스 원칙

1. **학습 앱처럼 보이지 않는다.**  
   점수, 진도바, 정답 표시보다 실제 메신저·이메일·근태 서비스와 유사하게 구성합니다.

2. **하루에 하나의 업무 맥락이 이어진다.**  
   상사와 거래처는 같은 업무 사건을 다른 관점에서 다루고, 동료는 업무와 연결된 캐주얼 대화를 나눕니다.

3. **상대에 따라 영어의 격식이 달라진다.**
   - 동료: 캐주얼 스몰토크
   - 상사: 업무 요청·보고·일정 조율
   - 거래처: 격식 있는 이메일·조건 협의

4. **대화 중에는 바로 채점하지 않는다.**  
   사용자의 답변이 모호하면 AI가 실제 상대처럼 되묻고, 교정과 설명은 퇴근 리포트에서 제공합니다.

5. **알림이 먼저 도착하는 경험이 핵심이다.**  
   사용자가 학습 화면을 찾아 들어가는 것이 아니라, 출근 후 업무 연락을 받는 구조로 구현합니다.

---

## 3. MVP 화면 범위

- 온보딩
- 출근 전·근무 중 홈
- 알림센터
- 동료·상사 메신저
- 거래처 이메일
- 반차·연차·출근 취소
- 퇴근 확인
- 영어 업무일지
- 설정

### 프론트 1차 연결 흐름

```text
근무 중 홈
→ 더미 알림 도착
→ 알림 클릭
→ 메신저 또는 이메일 화면 이동
→ 답변 입력
→ Mock 후속 반응 표시
```

---

## 4. 작업 분담

### 수아 담당

- 서비스 기획과 화면 정책 확정
- Supabase·Vercel·LLM API 계정 및 배포 관리
- DB와 출퇴근·휴가·외근 상태 로직
- 직무 기반 시나리오, 후속 반응, 퇴근 리포트 생성
- 알림 스케줄링과 실제 Web Push 발송
- 프론트 결과 검수 및 최종 화면 승인
- 발표와 시연 흐름 구성

### 윤경 님 담당

- 프론트엔드 화면 구현
- Service Worker 등록과 푸시 수신
- 알림 권한 요청 화면
- OS 알림 표시 및 클릭 라우팅
- 인앱 배너와 알림센터
- API 연결용 프론트 함수와 타입
- 반응형 화면 및 iOS 홈 화면 추가 안내

```text
[수아]
기획·데이터·LLM·상태 로직·푸시 발송
                     ↓ API / Push
[윤경 님]
화면·사용자 입력·푸시 수신·클릭 이동
```

> 프론트 구현은 윤경 님이 담당하되, 화면 구조와 정책은 본 문서 및 공유 명세를 기준으로 하고 주요 화면은 중간 배포본에서 함께 확인합니다.

## 5. Service Worker 역할

Service Worker는 서버가 아니라, 웹페이지가 열려 있지 않을 때도 브라우저에서 푸시를 받아주는 프론트 코드입니다.

```text
수아 서버에서 푸시 발송
→ Service Worker가 수신
→ OS 알림 표시
→ 알림 클릭
→ 해당 메신저·이메일 화면 이동
```

### 윤경 님 구현 범위

- Service Worker 등록
- 알림 권한 요청
- 푸시 구독 생성
- 더미 푸시 수신
- OS 알림 표시
- 알림 클릭 시 지정 경로 이동
- 가능한 환경에서 알림 액션 버튼 테스트

### 수아 구현 범위

- 푸시 구독 정보 저장 API
- 발송 시간 계산
- 예약 알림 조회
- 실제 Web Push 발송
- 외근 선택 시 재발송 스케줄 처리

---

## 6. 우선 작업 순서

### 1순위. 푸시 수신 관통 테스트

확인 항목:

- Service Worker가 정상 등록되는지
- 알림 권한을 받을 수 있는지
- 더미 푸시가 OS 알림으로 표시되는지
- 알림 클릭 시 지정 화면으로 이동하는지
- 데스크톱에서 알림 액션 버튼이 동작하는지
- 가능하면 iOS PWA에서 푸시 수신과 클릭 이동이 가능한지

**완료 기준:** 더미 알림을 누르면 지정한 메신저 또는 이메일 화면이 열립니다.

> iOS에서 알림 액션 버튼이 지원되지 않을 경우, 알림 클릭 후 대화 화면 상단의 `[지금 외근 중]` 버튼을 사용하는 대체 경로로 진행합니다.

### 2순위. 하드코딩 데이터 기반 UI 셸

우선 구현 화면:

1. 근무 중 홈
2. 동료·상사 메신저
3. 거래처 이메일
4. 우하단 인앱 배너
5. 알림센터
6. 퇴근 리포트

### 3순위. Mock 데이터와 프론트 타입

우선 필요한 데이터:

- 오늘의 근무 상태
- 오늘의 상황 3건
- 메시지·이메일 상세
- 사용자 답변 후 상대 반응
- 외근 처리 결과
- 퇴근 리포트

Mock JSON과 TypeScript 타입은 윤경 님이 초안을 작성하고, 실제 백엔드 구현 전 수아가 최종 필드명을 확정합니다.

---

## 7. 협업 방식

- 영어 프로젝트는 수아 계정의 Private 저장소에서 진행합니다.
- Supabase·Vercel·API 키와 환경변수는 수아 계정에서 관리하며 저장소에 직접 올리지 않습니다.
- 윤경 님은 프론트 작업을 별도 브랜치에서 진행하고 기능 단위로 자주 Push합니다.
- 첫 프론트 셸이 완성되면 임시 배포본으로 함께 화면 흐름을 확인합니다.
- 화면 구조, API 필드, 상태값 변경이 필요하면 구현 전에 공유합니다.
- 실제 API 연결 전 Mock 데이터 구조를 먼저 합의합니다.

## 9. MVP 완료 기준

아래 흐름이 실제로 동작하면 MVP 핵심이 완성된 것으로 봅니다.

```text
사용자가 출근한다.
→ 근무시간 중 동료·상사·거래처 연락이 도착한다.
→ 사용자가 영어로 답변한다.
→ 답변의 명확성에 따라 상대방이 자연스럽게 반응하거나 되묻는다.
→ 세 연락이 같은 업무 맥락으로 이어진다.
→ 퇴근 후 상대별 말투 차이와 교정이 포함된 업무일지가 생성된다.
```

> 온보딩·웹알림·업무회고·설정 화면의 구체적인 구현 스펙은 별도 문서 [frontend_feature_spec_for_yk.md](./frontend_feature_spec_for_yk.md)에 정리해뒀습니다.
