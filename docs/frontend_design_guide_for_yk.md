# 윤경님 우선 참고용 프론트 가이드 v1.0

> 목적: 영어 프로젝트 프론트 구현 시 전체 화면 톤과 공통 UI 방향을 맞추기 위한 참고 문서

---

## 1. 디자인 한 줄 방향

**영어 학습 앱이 아니라, 글로벌 회사의 업무용 협업 도구처럼 보이게 구현합니다.**

즉, 사용자가 문제를 푸는 느낌보다 실제 회사에서 메신저·이메일·근태 시스템을 사용하는 느낌이 나야 합니다.

---

## 2. 전체 콘셉트

### 키워드

- 업무용 SaaS
- 글로벌 오피스
- 차분한 B2B 툴
- 메신저 + 이메일 + 근태
- 학습 앱보다 업무 툴에 가까운 화면

### 참고 느낌

- Slack / Teams 계열 메신저 구조
- Gmail / Outlook 계열 이메일 구조
- Notion / Linear 계열의 정돈된 대시보드 느낌

> 특정 서비스를 그대로 복제하기보다, "정보 구조와 분위기"만 참고하는 방향으로 부탁드립니다.

---

## 3. 가장 중요한 원칙

### 1) 학습 앱처럼 보이면 안 됨

다음 요소는 최대한 지양합니다.

- 문제 번호
- 정답 / 오답 표시
- 시험지 같은 화면
- 큰 점수판
- 진도율 바
- 빨간색 문법 오답 강조
- "오늘의 영어 퀴즈" 같은 표현

### 2) 업무 상태가 먼저 보여야 함

이 서비스의 핵심은 영어를 공부한다기보다 **출근해서 연락을 받고 처리하는 경험**입니다.

그래서 첫 화면에서 우선 보여야 하는 건:

- 현재 근무 상태
- 다음 연락 예정
- 읽지 않은 메시지
- 오늘의 업무 흐름

입니다.

### 3) 메신저와 이메일은 확실히 달라야 함

- 동료 / 상사 = 메신저형
- 거래처 = 이메일형

채널 차이가 확실히 보여야 사용자가 "같은 영어라도 상대에 따라 다르게 말해야 한다"는 걸 체감할 수 있습니다.

---

## 4. 전체 톤 & 무드

### 원하는 분위기

- 깔끔함
- 차분함
- 실무적임

- 정보 중심

### 피하고 싶은 분위기

## 5. 공통 레이아웃 가이드

### 데스크톱 기준 권장 구조

```text
┌──────────────┬──────────────────────────────┐
│ 좌측 사이드바 │ 상단 바 (근무상태/시간/알림)   │
├──────────────┼──────────────────────────────┤
│ Home         │                              │
│ Messenger    │                              │
│ Email        │       주요 화면 콘텐츠        │
│ Reports      │                              │
│ Settings     │                              │
└──────────────┴──────────────────────────────┘
```

### 공통 원칙

- 좌측 사이드바는 주요 화면 공통 유지
- 상단에는 근무 상태 / 현재 시간 / 알림 관련 정보 노출
- 본문은 넓고 시원하게 사용
- 모바일에서는 사이드바를 햄버거 메뉴 또는 하단 탭으로 변환 가능

## 6. 화면별 가이드

## 6-1. 홈 화면

### 핵심 역할

오늘의 근무 상태와 오늘 처리할 연락 흐름을 한눈에 보여주는 화면

### 우선 보여야 하는 요소

- 출근 / 퇴근 상태
- 다음 연락 예정 시간
- 오늘의 연락 3건 상태
- 읽지 않은 메시지 수
- 퇴근하기 / 반차 사용 버튼

### 표현 방향

- 학습량보다 **업무 진행 상태**를 보여주는 느낌
- "오늘의 업무" 또는 "Today’s Workday" 같은 표현이 잘 어울림

---

## 6-2. 메신저 화면

### 핵심 역할

동료 / 상사와의 대화를 처리하는 업무 메신저

### 구조

- 좌측: 대화 목록
- 우측: 대화 상세
- 상대방 이름, 직급, 최근 활동 표시 가능

### 표현 방향

#### 동료
- 캐주얼
- 짧은 문장
- 자연스러운 스몰토크 느낌

#### 상사
- 요청 / 확인 / 진행상황이 명확히 보이게
- 일정, 마감, 부탁 내용이 잘 드러나게

### 주의

- ChatGPT처럼 생긴 일반 AI 채팅창 느낌은 피하기
- "AI" 표시는 너무 전면에 내세우지 않기

---

## 6-3. 이메일 화면

### 핵심 역할

거래처와의 격식 있는 커뮤니케이션 처리

### 꼭 필요한 요소

- 발신자
- 제목
- 수신 시각
- 본문
- 회신 입력창
- 이전 메일 스레드

### 표현 방향

- 메신저보다 훨씬 정돈되고 포멀한 느낌
- 거래처와의 거리감이 메신저와 시각적으로 구분되게

---

## 6-4. 업무일지 / 리포트 화면

### 핵심 역할

퇴근 후 오늘 사용한 표현을 정리해주는 화면

### 표현 방향

- 성적표처럼 보이면 안 됨
- "하루 업무 회고" 문서처럼 보이면 좋음
- 오늘의 업무 요약 → 잘한 표현 → 수정 포인트 → 내일 이어질 내용 순서 추천

### 주의

- 틀린 문장을 과하게 붉게 표시하지 않기
- 사용자를 평가하거나 혼내는 느낌 금지

---

## 7. 컬러 가이드

구체적인 컬러코드는 자유롭게 잡으셔도 되지만, 전체 방향은 아래처럼 부탁드립니다.

### 기본 방향

- 배경: 화이트 / 옅은 그레이
- 본문 텍스트: 진한 그레이 계열
- 포인트 컬러: 1개 메인 컬러 위주
- 상태 색상은 최소한으로 사용

### 상태 색상 예시

- 완료 / 성공: 초록 계열
- 예정 / 대기: 블루 또는 중립 계열
- 주의 / 마감 임박: 오렌지 계열
- 오류: 시스템 오류에만 레드 사용

> 영어 표현 오류를 붉은색 오답처럼 표시하지는 않는 방향이면 좋겠습니다.

## 8. 공통 컴포넌트 권장

가능하면 아래 요소는 공통 컴포넌트로 구성 부탁드립니다.

- 사이드바
- 상단 상태 바
- 기본 버튼
- 상태 배지
- 메시지 말풍선
- 이메일 카드
- 우하단 인앱 배너
- 확인 모달
- 빈 상태 화면
- 로딩 상태
- 에러 상태

---

## 9. 1차 UI 확인 시 체크 기준

1차로 하드코딩 UI 셸이 나왔을 때 아래를 기준으로 같이 확인하면 될 것 같습니다.

- 첫 화면이 영어 학습 앱보다 업무 툴처럼 보이는가
- 출근 / 퇴근 / 업무 처리 흐름이 자연스러운가
- 메신저와 이메일이 명확히 구분되는가
- 동료 / 상사 / 거래처의 거리감이 화면에서 느껴지는가
- 홈 → 메신저 → 이메일 → 리포트 흐름이 무리 없이 이어지는가
- 모바일에서도 최소한 핵심 흐름이 보이는가

---

## 10. 우선순위

디자인 완성도보다 우선인 것은 아래입니다.

1. 구조가 명확할 것
2. 업무용 툴처럼 보일 것
3. 메신저 / 이메일 차이가 확실할 것
4. 출근부터 퇴근까지 흐름이 보일 것
5. 이후 API 연결이 쉬운 구조일 것

---
